# LEADUP CRM

Операционная система руководителя отдела холодной лидогенерации.

Операторы звонят в Скорозвоне. В систему попадает только конечный результат —
**лид, успешно переданный менеджеру**. На основе переданных лидов, смен, планов и
состава команды система считает: сколько сделано, сколько осталось, каким темпом
идём, что будет к концу месяца (Run Rate), кто выполняет план и кто отстаёт,
сколько лидов команда делает за час и сколько нужно выплатить каждому.

Стек: Next.js 14 (App Router, статический экспорт) + TypeScript + React, графики —
recharts. Есть сборка под десктоп (Electron).

## Запуск

```bash
npm install          # если node_modules ещё нет
npm run dev          # http://localhost:3000
```

При первом запуске база пустая: заведите проекты, группы и операторов на «Сводке»,
планы — в «Планах» и карточках, цену лида для заказчика — в «Настройках».

Проверки:

```bash
npm run test:calc     # формулы: план на дату, RR, темп, статусы, зарплата, фиксация месяцев, импорт
npm run check:routes  # каждый пункт меню и каждая внутренняя ссылка ведут на существующую страницу
npx tsc --noEmit      # типы
npm run build         # статическая сборка в out/
```

## Роли и аккаунты

| Роль | Что видит | Что может |
|---|---|---|
| **РОП** | весь отдел | всё: операторы, группы, планы, график, зарплата, проекты, настройки, данные, аккаунты |
| **Супервайзер** | только свои группы (назначенные в аккаунте + где он руководитель группы) | по настройке РОПа: вносить и править лиды, вести операторов и график, ставить планы, смотреть и менять зарплату своей группы |
| **Оператор** | только себя | вносить свои лиды (и править их в течение N часов), видеть свой план, часы, заработок и — если разрешено — результат группы |

Видимость реализована срезом данных (`lib/crm/access.ts` → `scopeData`): страницы и расчёты получают
DataState, урезанный до зоны аккаунта, поэтому чужие записи просто отсутствуют. Все действия дополнительно
проверяются в хранилище — кнопки скрыты и операция не пройдёт, даже если её вызвать в обход интерфейса.

Что разрешено супервайзерам и операторам, настраивается на вкладке «Роли и доступ» без правки кода.

**Вход пока выключен** (`AUTH_ENABLED = false`), поэтому аккаунт переключается из меню внизу слева без пароля —
так удобно проверить, как систему видят РОП, супервайзер и оператор. Когда вход вернётся, `login` аккаунта станет
логином, а права останутся теми же.

## Как устроены данные

```
lib/crm/
  types.ts     сущности и подписи
  db.ts        IndexedDB: отдельное хранилище на сущность, запись по одной записи
  store.tsx    состояние и все действия (добавить лид, перевести оператора, …)
  calc.ts      аналитика — чистые функции, ничего не пишут
  payroll.ts   расчёт зарплаты
  validate.ts  проверка целостности, приём импорта
  dates.ts     даты без часовых поясов ("YYYY-MM-DD")
  demo.ts      тестовый набор данных для npm run test:calc (в приложении не используется)
```

- **Исходные данные отдельно от аналитики.** Операторы, группы, проекты, лиды,
  смены, планы месяцев, корректировки зарплаты и настройки лежат в IndexedDB.
  Все показатели считаются на лету и нигде не хранятся — перестройка экрана
  не может испортить данные.
- **Точечные записи.** Новый лид = одна запись, правка оператора = одна запись,
  смена = одна запись с ключом `дата|оператор`. Полная перезапись — только при
  импорте/восстановлении, одной транзакцией и после резервной копии.
- **Связи по ID.** Лид хранит ID оператора, проекта и группы оператора *на момент
  передачи* — переводы между группами не переписывают историю.
- **Удаление без потери истории.** Оператор, группа и проект удаляются «мягко»:
  пропадают из списков и форм, а их лиды, смены и начисления остаются в отчётах.
  Сотрудники удалённой группы уходят в «Без группы».
- **Прошлые месяцы фиксируются автоматически**: планы, нормы и ставки того
  месяца записываются отдельно, поэтому правка карточки сегодня не пересчитает
  прошлое. Текущий месяц можно зафиксировать вручную на странице «Зарплата».
- **Резервные копии**: раз в сутки и перед каждой опасной операцией (удаление,
  импорт, восстановление, очистка). Список и восстановление — в Настройках.
- Несколько вкладок синхронизируются между собой (BroadcastChannel).
- **Шрифты лежат в репозитории** (`app/fonts`): Inter на весь текст, JetBrains Mono на цифры.
  Inter выбран из-за полной кириллицы — шрифт без неё набирает русскую строку двумя гарнитурами
  сразу (буквы системным фолбэком, латиница и цифры своими), и интерфейс выглядит рваным.
  Стек один на всё приложение: токены `--font-sans` и `--font-mono` в `app/globals.css`.

### Формулы

- План на дату = план месяца × прошедшие рабочие дни / рабочие дни месяца
- RR (прогноз) = факт / прошедшие рабочие дни × рабочие дни месяца
- Нужно в день = (план − факт до сегодня) / оставшиеся рабочие дни, включая сегодня
- Статус: факт / план на дату ≥ 110% — выше плана, ≥ 95% — по плану, ≥ 80% —
  отстаёт, ниже — сильно отстаёт; N рабочих дней без лидов (не считая отпуск и
  больничный) — не работает. Пороги меняются в Настройках.
- Новичкам и уволенным посреди месяца план и норма уменьшаются пропорционально
  рабочим дням в штате.
- Зарплата: оклад × min(1, часы / норма) или часы × ставка; + бонус за лиды;
  + начисления; − удержание % (компенсации не облагаются); − удержания;
  − аванс и выплаты = остаток.

### Оплата оператора: ставка зависит от смены

Ставка за час и деньги за лид растут вместе с результатом смены. Считается по каждому дню отдельно:

| Лидов за смену | Ставка в час | За каждый лид |
|---|---|---|
| 0–5 | 200 ₽ | 70 ₽ |
| 6–7 | 230 ₽ | 75 ₽ |
| 8–10 | 240 ₽ | 80 ₽ |
| 11 и больше | 260 ₽ | 90 ₽ |

**Ставка часа пересчитывается на всю смену**: восьмой лид поднимает не только цену лида, но и стоимость
каждого отработанного часа. Смена 8 ч с 5 лидами — 200 × 8 + 70 × 5 = 1 950 ₽; те же 8 ч с 8 лидами —
240 × 8 + 80 × 8 = 2 560 ₽.

Сетки заводятся в Настройках → Система (их может быть несколько), назначаются в карточке оператора.
В ведомости есть разбор: сколько смен прошло по каждой ступени и сколько по ней начислено. Оператор в
своём кабинете видит текущую ступень и сколько лидов осталось до следующей.

### Прогноз ФОТ

В текущем месяце рядом с таблицей ФОТ показывается прогноз: фонд растёт пропорционально отработанным дням,
доход — по Run Rate лидов. Если по текущему темпу норматив будет пробит, строка краснеет и говорит,
**в какой день** это произойдёт и сколько лидов нужно за месяц, чтобы уложиться.

### Апрув заказчика

Проценты принятых лидов задаются по проектам на месяц (`Зарплата → Апрув заказчика`), плюс общий процент месяца
для проектов без своего значения. Бонус супервайзера берёт **средневзвешенный по числу переданных лидов** процент —
вручную в ведомость ничего вбивать не нужно, а история сохраняется по месяцам.

### Стажировка

Новичок считается стажёром, пока не наберёт норму: по умолчанию 10 лидов за 15 отработанных часов
(`Настройки → Система`). Считается с даты приёма и по всем месяцам, поэтому переход через первое число
не обнуляет прогресс. Прогресс виден в карточке оператора и в кабинете новичка, дата закрытия проставляется сама.

### Журнал изменений

Каждая правка плана, ставки, схемы оплаты, смены, начисления, апрува и настроек пишется в журнал:
кто, когда и что изменил («Ставка: 200 → 230 ₽»). Хранятся последние 3000 записей, они попадают в выгрузку
и резервные копии. Смотреть — `Настройки → Журнал`.

### Утро руководителя

Карточка на «Сводке»: кто сегодня без смены, кто на смене без единого лида и кто вчера отработал ниже нормы
конверсии (норма = лиды ÷ часы из условий стажировки). Клик по имени открывает карточку оператора.

### ФОТ и норматив

Доход считается по цене лида для заказчика (`Настройки → Система → Зарплата`), фонд оплаты труда — по фактическим
начислениям ведомости. Норматив задаётся в процентах от дохода (по умолчанию 24%) и показывается тремя местами:

- **Зарплата** — плитка «ФОТ к доходу» и таблица по группам: лиды, доход, ФОТ, % и запас до норматива;
- **Группы** — плитка «ФОТ к доходу» в карточке группы;
- **Карточка супервайзера в ведомости** — ФОТ его групп, % и сколько ещё можно добрать до норматива.

Превышение подсвечивается красным. Формула: `ФОТ % = начислено / (лиды × цена лида)`.

### Мотивация супервайзера

Оклад 45 000 ₽ плюс бонус за объём лидов его групп за месяц — по ступеням, грейду (Junior / Middle / Senior)
и направлению (недвижимость или авто):

| Лидов за месяц | Недвижимость Jr / Mid / Sr | Авто Jr / Mid / Sr |
|---|---|---|
| до 700 | бонуса нет | бонуса нет |
| 700 | 4 000 / 4 500 / 5 000 | 3 500 / 4 000 / 4 500 |
| 1 000 | 16 000 / 18 000 / 20 000 | 15 000 / 17 000 / 19 000 |
| 1 200 | 25 000 / 27 000 / 30 000 | 24 000 / 26 000 / 29 000 |
| 1 500 | 40 000 / 43 000 / 45 000 | 40 000 / 42 000 / 44 000 |
| 1 750 | 50 000 / 52 000 / 55 000 | 49 000 / 51 000 / 54 000 |
| 2 000 | 60 000 / 65 000 / 70 000 | 58 000 / 63 000 / 68 000 |

Поправки: апрув заказчика от 30% — коэффициент 1, от 25% — 0,95, от 20% — 0,9, ниже 20% — бонус обнуляется;
нет роста к прошлому месяцу — 0,85 (кроме Junior). Объём берётся по группам, где сотрудник указан
руководителем; рост считается автоматически по прошлому месяцу, апрув проставляется в ведомости, в условиях
месяца. Норматив «ФОТ группы не выше 24% от дохода» система не проверяет — это подтверждает руководитель направления.

## Обучение («Академия обзвона»)

Раздел **Обучение** — исходная академия целиком, а не пересказ: курсы, модули, материалы, разделы и тексты
переносятся скриптом `npm run import:academy <файл.html>` и лежат в `lib/learn/content.json`.
Руками этот файл не правим — иначе следующая выгрузка затрёт правки.

**Структура — как в источнике.** Слева разделы роли:

| Роль | Разделы |
|---|---|
| Оператор | Обучение: Главная, Курсы, Тесты, Мой прогресс · В звонке: Скрипты, Возражения, Статусы, Чек-листы · Справочники: Новостройки, Авто, Города, Оплата и оформление, Глоссарий · Личное: Мои заметки |
| Супервайзер и РОП | Обучение: Главная, Курсы, Тесты, Мой прогресс · В работе: Скрипт интервью, Чек-листы, Регламенты, Мотивация и бонус, Базы и лиды · Для группы: Материалы операторов, Обучение команды · Личное: Мои заметки |

- 8 курсов, 96 материалов: операторские (недвижимость, авто), супервайзерские (найм, управление группой,
  деньги и базы, шпаргалки), тренажёры и справочники.
- Уроки разбиты на пронумерованные шаги, как в исходнике: таблицы, выноски, скрипты «говорим дословно»
  с кнопкой «Скопировать», диалоги, чек-листы с отметками.
- Порядок жёсткий: следующий материал открывается после предыдущего, модуль закрывается тестом.
  Тест — 80%, разбор каждой ошибки, «Повторить перед пересдачей» с подбором уроков по темам ошибок,
  учёт лучшего результата и числа попыток, сертификат за итоговую аттестацию.
- Справочники с поиском, фильтрами и подсветкой совпадений: вилки цен по городам, статусы Скорозвона
  по обоим направлениям, возражения, глоссарий, цены авто, города и расстояния до ДЦ.
  В разделах и в боковой панели они же открываются поверх страницы, не теряя места в материале.
- Тренажёры: карточки возражений и выбор статуса по ситуации.

**Чем отличается от исходного файла — намеренно:**

- калькуляторы смены и бонуса считают по настройкам платформы (`Настройки → Система`), а не по вшитым
  числам, поэтому обучение и ведомость не могут разойтись;
- прогресс, заметки, избранное и сертификаты хранятся в аккаунте, а не в localStorage браузера,
  поэтому видны на любом устройстве и не теряются при очистке кэша;
- добавлен раздел «Обучение команды» для супервайзера и РОПа: кто сколько прошёл и сколько тестов сдал.

## Авторизация (спрятана)

Сейчас вход выключен: `lib/appMode.ts → AUTH_ENABLED = false`. Весь код входа
сохранён — `lib/auth.ts`, `lib/supabase.ts`, страницы `app/(public)/login|signup|reset`,
`components/auth/authKit.tsx`. Пока флаг выключен, CRM открывается сразу, а страницы
входа уводят на «Сводку». Чтобы вернуть — поставить `true`: `components/app/AuthGate.tsx`
снова начнёт требовать сессию.

Папка `supabase/` — от прежнего приложения (Vexi), к CRM не относится. Когда
будем подключать вход и общую базу, схему CRM нужно будет завести заново, а
`lib/crm/db.ts` заменить адаптером к серверу с тем же набором функций.

> Пока данные хранятся в браузере конкретного компьютера. Для работы нескольких
> руководителей с одними данными нужен сервер — это следующий шаг вместе с авторизацией.
